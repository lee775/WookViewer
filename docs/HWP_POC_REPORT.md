# HWP / HWPX 렌더 PoC 보고서

**작성일**: 2026-05-07
**범위**: 김총괄 게이트 #1 — HWP 렌더 1주 PoC. hwplib(HWP 5.0) + hwpxlib(HWPX) 라이브러리로
"표·이미지·한글 텍스트가 식별 가능한 수준"으로 모바일에서 보일 수 있는지 검증.

---

## 1. 도입 라이브러리

| 라이브러리 | 버전 | Maven Central | 용도 |
|---|---|---|---|
| `kr.dogfoot:hwplib` | 1.1.9 (2025-04) | ✅ | HWP 5.0 (바이너리, 한컴 OLE) 파싱 |
| `kr.dogfoot:hwpxlib` | 1.0.8 (2025-11) | ✅ | HWPX (한컴 OWPML, ZIP 기반) 파싱 |

둘 다 **Java 7 호환 + Apache 2.0 라이선스** → 안드로이드/상업 배포에 문제 없음.

`hwplib`는 Apache POI 3.9를 번들로 들고 온다 — APK 사이즈/dex 크기에 영향.

---

## 2. 구현 범위 (PoC에서 한 것)

### ✅ 작동
- SAF URI에서 임시 캐시로 복사 후 `HWPReader.fromFile()` / `HWPXReader.fromFilepath()` 로 파싱
- 확장자 + 매직바이트 (`PK..`) 로 HWP / HWPX 자동 분기
- `TextExtractor.extract()` 로 본문 텍스트 일괄 추출
- 텍스트 길이 기반 **논리 페이지 분할** (1500자/페이지)
- Android `Canvas` + `StaticLayout` 으로 A4 비율 Bitmap 렌더
- 시스템 한글 폰트 폴백 (Noto CJK)
- 통합 뷰어 화면이 PDF와 동일한 UI로 HWP를 표시
- 단위 테스트 5개 (HwpPaginator)

### ⚠️ 제한 (의도적, 명시적)
| 항목 | 동작 | 이유 |
|---|---|---|
| 표 (Table) | 무시 (TextExtractor가 셀 텍스트만 inline 추출) | 본격 표 렌더는 별도 레이아웃 엔진 필요 |
| 이미지 / 도형 | 무시 | 비트맵 추출 + 위치 매핑 미구현 |
| 폰트 / 크기 / 색상 | 일괄 기본값 (16px, 검정) | 서식 적용은 v0.3 범위 |
| 페이지 번호 | 원본 한글 페이지와 불일치 | 진짜 페이지는 렌더 시 결정. 논리 분할로 대체 |
| 머리말/꼬리말 | 무시 | 본문만 |
| 수식 (수식편집기) | 텍스트 형태로 추출됨 (왜곡 가능) | OWPML/HWP 수식 → MathML 변환 미구현 |
| 암호화된 HWP | `HwpOpenException` | hwplib가 미지원 |

### ❌ 검증 못한 것 (실측 필요)
- 100MB 이상 대용량 HWP 메모리 거동
- 파일 1000개로 회귀 테스트
- 한글 2002 이전 구버전 HWP (3.0/97) — hwplib는 5.0만 지원

## 3. 김총괄 게이트 판정 자료

> 게이트 조건: "hwplib로 표/이미지/한글 텍스트가 식별 가능한 수준으로 렌더 되는지 증명"

| 게이트 항목 | 결과 | 근거 |
|---|---|---|
| 한글 텍스트 식별 가능 | ✅ **PASS** | TextExtractor가 한글 정상 반환, StaticLayout이 Noto CJK 폴백으로 그림 |
| 표 식별 가능 | ⚠️ **부분** | 표 셀의 *텍스트 내용*은 추출되나 *표 구조*는 인라인 텍스트로 평탄화됨 |
| 이미지 식별 가능 | ❌ **FAIL** | 현 PoC 범위 밖. hwplib는 BinData를 파싱하지만 본 PoC에서 활용 안 함 |

### 종합 의견 (박설계 → 김총괄)

본 PoC는 **"보기는 되지만 한글 원본 그대로는 아님"** 수준이다.
사용자가 받는 가치:
- ✅ 텍스트 내용을 모바일에서 빠르게 확인 (검색/회신 목적)
- ❌ 원본과 동일한 레이아웃 보기 (계약서/공문 등 정합성 중요 문서)

**권고 옵션 3가지**:

#### 옵션 A. 현재 PoC 수준으로 v0.2 출시
- "텍스트 미리보기" 기능으로 명시적 마케팅 (오해 방지 UI 필요)
- 기간: 추가 1주 (UI 안내, 에러 메시지 다듬기)
- 비용: 0
- 리스크: 사용자 기대치 미스매치 → 평점 하락

#### 옵션 B. 표·이미지 포함 본격 렌더 자체 구현
- hwplib `Section.ParagraphList` 트리를 직접 순회하며
  표는 `Cell` 단위로 그리고, `BinData` 이미지를 `Bitmap`으로 디코드
- 기간: **추가 4-6주** (시니어 1명)
- 비용: 0 (라이브러리 무료)
- 리스크: 한글 레이아웃 엔진 재구현은 본질적으로 어려움 — 끝없이 깨지는 이슈

#### 옵션 C. 변환 서버 도입 (안 B 부분 도입)
- 디바이스가 HWP를 서버로 업로드 → LibreOffice/Hancom 컨버터로 PDF 변환 → 다운로드 후 PdfRenderer로 표시
- 기간: 추가 3주 (서버 구축 + 클라이언트 변환 흐름)
- 비용: 서버 운영비 + 보안 검토 (사용자 문서 일시 업로드)
- 리스크: 오프라인 미지원, GDPR/개인정보 검토 필수
